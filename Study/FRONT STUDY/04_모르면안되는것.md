# 프론트엔드 모르면 안 되는 것

## 1. 브라우저 렌더링 과정

```
HTML 파싱 → DOM 트리 생성
CSS 파싱 → CSSOM 트리 생성
DOM + CSSOM → Render Tree 생성
Layout(Reflow): 요소의 위치/크기 계산
Paint: 픽셀 그리기
Composite: 레이어 합성
```

**성능에 영향:**
- `display`, `width`, `height`, `top`, `left` 변경 → Reflow(레이아웃 재계산) 발생 (비용 높음)
- `color`, `opacity`, `background` 변경 → Repaint만 발생 (비용 낮음)
- `transform`, `opacity` → GPU 처리 가능 (애니메이션에 최적)

이 프로젝트에서:
```css
/* Reflow 없는 호버 효과 */
.card:hover {
    transform: translateY(-2px);  /* GPU 처리 */
    box-shadow: 0 8px 24px ...;   /* Repaint */
    /* top: -2px 대신 transform 사용 */
}
```

## 2. HTTP 요청 흐름 (브라우저 관점)

```
사용자: /news 입력
→ DNS 조회 (newsdeliver.onrender.com → IP)
→ TCP 연결 (3-way handshake)
→ TLS 핸드셰이크 (HTTPS)
→ HTTP GET /news 요청
→ 서버: DB 조회 → Jinja2 렌더링 → HTML 반환
→ 브라우저: HTML 파싱
→ CSS/JS/이미지 추가 요청 (병렬)
→ 페이지 렌더링 완료
```

**브라우저 캐시:**
```html
<!-- 정적 파일 캐시 버스팅 -->
<link rel="stylesheet" href="/static/css/main.css?v=3.8">
```
- 브라우저는 URL이 같으면 캐시된 파일 사용
- `?v=3.8` 버전을 바꾸면 새로 다운로드

## 3. 쿠키 동작 원리 (브라우저)

```
로그인 POST 요청
→ 서버 응답: Set-Cookie: newsletter_user=user123; HttpOnly; SameSite=Lax
→ 브라우저가 쿠키 저장

다음 요청 (같은 도메인)
→ 브라우저가 자동으로 Cookie: newsletter_user=user123 헤더 추가
→ 서버가 쿠키에서 user_id 읽어 인증

로그아웃
→ 서버: Set-Cookie: newsletter_user=; Max-Age=0 (쿠키 삭제)
```

**브라우저에서 쿠키 확인:**
- 개발자 도구 → Application → Cookies → 도메인 선택
- `httponly` 쿠키는 JS `document.cookie`에서 보이지 않음

## 4. 폼 제출 방식 비교

| 방식 | 코드 | 특징 |
|------|------|------|
| HTML 폼 (동기) | `<form method="POST">` | 페이지 새로고침 됨 |
| fetch API (비동기) | `fetch('/api', {method:'POST'})` | 새로고침 없음 |
| AJAX (구형) | `XMLHttpRequest` | fetch 등장 전 방식 |

**이 프로젝트에서의 혼용:**
- 로그인, 회원가입, 구독 → HTML 폼 (PRG 패턴)
- 좋아요, 북마크, 댓글, 카테고리 구독 → fetch API (페이지 유지)

**HTML 폼 → fetch 변환 패턴:**
```javascript
document.querySelector('form').addEventListener('submit', async (e) => {
    e.preventDefault();  // 기본 폼 제출 방지
    
    const formData = new FormData(e.target);  // 폼 데이터 자동 수집
    
    const res = await fetch('/api/subscribe', {
        method: 'POST',
        body: formData
    });
    
    if (res.ok) {
        showSuccess();
    }
});
```

## 5. 크로스 브라우저 이슈

**CSS 벤더 프리픽스 (구형 브라우저 지원):**
```css
/* 현재는 대부분 불필요하지만 알고 있어야 함 */
-webkit-transform: translateY(-2px);  /* Safari 구버전 */
-moz-transform: translateY(-2px);     /* Firefox 구버전 */
transform: translateY(-2px);          /* 표준 */
```

**이메일 HTML의 특수성:**
```html
<!-- 이메일 클라이언트는 웹 브라우저보다 CSS 지원이 훨씬 제한적 -->
<!-- Flexbox, Grid → 많은 클라이언트에서 미지원 -->
<!-- 대신 table 레이아웃, 인라인 스타일 사용 -->

<table width="600" cellpadding="0" cellspacing="0">
  <tr>
    <td style="background:#c00; color:white; padding:20px;">
      헤더 내용
    </td>
  </tr>
</table>
```

## 6. 접근성 (Accessibility)

```html
<!-- alt 텍스트: 스크린리더가 이미지를 설명 -->
<img src="{{ news.image_url }}" alt="{{ news.title }}" />
<img src="decoration.png" alt="" />  <!-- 장식용 이미지는 빈 alt -->

<!-- 버튼: 명확한 레이블 -->
<button aria-label="좋아요" onclick="toggleLike()">♥</button>

<!-- 키보드 접근: tabindex -->
<div tabindex="0" onkeydown="if(e.key==='Enter') toggle()">클릭 가능 div</div>

<!-- 색상 대비: 4.5:1 이상 (WCAG AA 기준) -->
/* #c00 빨간색 배경에 흰색 텍스트 → 대비율 양호 */
color: white;
background: #c00;

<!-- 포커스 스타일: 키보드 사용자를 위해 제거하지 말 것 -->
button:focus { outline: 2px solid #0066cc; }
```

## 7. SEO (Search Engine Optimization)

```html
<!-- 핵심 메타 태그 -->
<meta charset="UTF-8">
<meta name="viewport" content="width=device-width, initial-scale=1.0">
<meta name="description" content="뉴스레터 구독 서비스">

<!-- Open Graph (소셜 미디어 공유 시 미리보기) -->
<meta property="og:title" content="{{ news.title }}">
<meta property="og:description" content="{{ news.content[:100] }}">
<meta property="og:image" content="{{ news.image_url }}">
<meta property="og:url" content="https://newsdeliver.com/news/{{ news.id }}">

<!-- 구조화된 데이터 -->
<title>{{ news.title }} - News Delivery</title>  <!-- 구체적인 제목 -->
<h1>...</h1>  <!-- 페이지당 하나만 -->
<h2>, <h3>   <!-- 계층 구조 유지 -->
```

**SSR이 SEO에 유리한 이유:**
- 구글 봇이 페이지에 접근하면 완성된 HTML을 즉시 받음
- CSR(React 등)은 JS 실행 후 콘텐츠가 생성되어 크롤링이 어려울 수 있음

## 8. 웹 성능 최적화

### 이미지 최적화
```html
<!-- lazy loading: 스크롤 시 로드 -->
<img src="{{ image_url }}" loading="lazy" alt="{{ title }}">

<!-- 이미지 사이즈 명시 (CLS 방지) -->
<img src="..." width="400" height="300" alt="...">

<!-- 반응형 이미지 -->
<img src="small.jpg"
     srcset="medium.jpg 768w, large.jpg 1200w"
     sizes="(max-width: 768px) 100vw, 50vw">
```

### CSS/JS 로딩 최적화
```html
<!-- CSS: head에서 로드 (렌더링 차단) -->
<link rel="stylesheet" href="style.css">

<!-- JS: body 끝이나 defer로 로드 (파싱 차단 방지) -->
<script src="script.js" defer></script>
<script src="script.js" async></script>
<!-- defer: DOM 파싱 완료 후 실행 (순서 보장) -->
<!-- async: 다운로드 완료 즉시 실행 (순서 불보장) -->
```

### 렌더링 성능
```javascript
// 나쁜 예: DOM 조작을 반복 (Reflow 유발)
items.forEach(item => {
    document.body.style.height = ...;  // 매번 계산
    container.appendChild(el);          // 매번 Reflow
});

// 좋은 예: DocumentFragment로 일괄 처리
const fragment = document.createDocumentFragment();
items.forEach(item => {
    const el = document.createElement('div');
    el.textContent = item.title;
    fragment.appendChild(el);
});
container.appendChild(fragment);  // 한 번만 DOM에 추가
```

## 11. 자주 실수하는 것들

### `===` vs `==`
```javascript
// JavaScript: 항상 === 사용 (타입 포함 비교)
'true' === 'true'   // true
'true' === true     // false (타입 다름)
btn.dataset.liked === 'true'  // dataset은 항상 string!

// Python: == 사용
'true' == 'true'    # True
```

### `async function` 빠뜨리기
```javascript
// 틀림: await 앞에 async 없으면 SyntaxError
function loadData() {
    const data = await fetch('/api');  // ❌
}

// 맞음
async function loadData() {
    const data = await fetch('/api');  // ✅
}
```

### Jinja2 변수 이름 오타
```html
{{ current_user.id }}    ← id (소문자)
{{ current_user.name }}  ← name (소문자)
{{ news.created_at }}    ← created_at (언더스코어)
```

### CSS z-index가 동작 안 할 때
```css
/* z-index는 position이 있어야 동작 */
.element {
    position: relative;  /* 또는 absolute, fixed, sticky */
    z-index: 100;        /* position 없으면 무시됨 */
}
```

### `display: none` vs `visibility: hidden`
```css
display: none;       /* 공간도 차지하지 않음 (레이아웃에서 제거) */
visibility: hidden;  /* 보이지 않지만 공간은 유지 */
opacity: 0;          /* 투명하지만 공간+이벤트 유지 */
```
