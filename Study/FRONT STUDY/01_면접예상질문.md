# 프론트엔드 면접 예상 질문 (NewsDeliver 기반)

## 1. 렌더링 방식 관련

### Q. SSR(Server-Side Rendering)이란 무엇이고, 이 프로젝트에서 어떻게 사용했나요?
**A.**
- SSR은 서버에서 HTML을 완성해 브라우저에 전달하는 방식입니다.
- 이 프로젝트는 FastAPI + Jinja2 템플릿 엔진을 사용하여 서버에서 데이터를 조회하고 HTML을 렌더링한 뒤 완성된 페이지를 전송합니다.
- 사용자가 `/news`에 접근하면 서버가 DB에서 뉴스를 조회하고 `news.html`에 데이터를 넣어 완성된 HTML을 반환합니다.

### Q. SSR과 CSR(Client-Side Rendering)의 차이점은?
| 구분 | SSR (이 프로젝트) | CSR (React 등) |
|------|------------------|----------------|
| 렌더링 위치 | 서버 | 브라우저 |
| 초기 로드 | HTML 완성본 전달 | 빈 HTML + JS 번들 |
| SEO | 유리 (크롤러가 HTML 읽음) | 불리 (JS 실행 전 빈 페이지) |
| 인증 | 쿠키 기반 자연스러움 | JWT + localStorage 주로 |
| 추가 상호작용 | JS로 일부 동적 처리 | 모두 JS로 처리 |

## 2. HTML 관련

### Q. 시맨틱 태그(Semantic HTML)란 무엇인가요?
**A.**
- 의미를 가진 HTML 태그를 사용하여 구조를 명확히 하는 것입니다.
- `<div>` 대신 `<header>`, `<nav>`, `<main>`, `<article>`, `<footer>` 등 사용
- 이 프로젝트: `<header class="site-header">`, `<nav class="main-nav">`, `<main>` 구조 사용
- 장점: SEO 향상, 스크린리더 접근성 향상, 코드 가독성 향상

### Q. `data-*` 속성이란 무엇인가요?
**A.**
- HTML 요소에 커스텀 데이터를 저장하는 표준 방식입니다.
```html
<div class="detail-container"
     data-news-id="{{ news.id }}"
     data-user-id="{{ current_user.id if current_user else '' }}"
     data-logged-in="{{ 'true' if current_user else 'false' }}">
```
```javascript
const newsId = document.querySelector('.detail-container').dataset.newsId;
const isLoggedIn = document.querySelector('.detail-container').dataset.loggedIn === 'true';
```
- 서버에서 렌더링한 데이터를 JS에서 접근할 때 유용합니다.

### Q. `target="_blank"`에 `rel="noopener"`를 추가하는 이유는?
**A.**
- `target="_blank"`로 새 탭을 열면 열린 페이지가 `window.opener`로 부모 페이지에 접근할 수 있습니다.
- 악의적인 외부 사이트가 부모 페이지를 조작하는 **Reverse Tabnapping** 공격이 가능합니다.
- `rel="noopener"`로 이 연결을 차단합니다.
- 이 프로젝트: `<a href="{{ news.link }}" target="_blank" rel="noopener">`

## 3. CSS 관련

### Q. CSS Box Model이란?
**A.**
- 모든 HTML 요소는 content → padding → border → margin 순으로 구성됩니다.
- `box-sizing: border-box`: 이 프로젝트에서 전역 설정 (`* { box-sizing: border-box; }`)
  - `border-box`: width/height가 border와 padding을 포함 (직관적)
  - `content-box` (기본값): width/height가 content만 포함 (padding 추가 시 예상보다 커짐)

### Q. CSS Flexbox를 어떻게 사용했나요?
**A.**
```css
/* 헤더 레이아웃 */
.header-top {
    display: flex;
    align-items: center;    /* 세로 가운데 정렬 */
    position: relative;
}
.header-left { flex: 1; }  /* 남은 공간 차지 */

/* 아이콘 + 텍스트 정렬 */
.nav-icon {
    display: inline-flex;
    align-items: center;
    justify-content: center;  /* 가로 세로 모두 가운데 */
}
```

**핵심 속성:**
- `flex-direction`: row(가로, 기본) / column(세로)
- `justify-content`: 주축 정렬 (center, space-between, flex-start 등)
- `align-items`: 교차축 정렬 (center, stretch 등)
- `flex: 1`: 남은 공간을 모두 차지 (`flex-grow: 1`의 단축형)
- `gap`: 자식 요소 간격

### Q. CSS `position` 속성의 종류와 차이는?
**A.**
```css
/* static: 기본값, 위치 속성 무시 */
/* relative: 원래 위치 기준 이동, 공간 유지 */
.badge {
    position: relative;  /* 자식 absolute의 기준점 */
}

/* absolute: 가장 가까운 positioned 조상 기준, 공간 차지 안 함 */
.badge-count {
    position: absolute;
    top: -8px;
    right: -8px;  /* 부모 right-top에 붙음 */
}

/* fixed: 뷰포트(화면) 기준, 스크롤에도 고정 */
.site-header {
    position: sticky;  /* 스크롤 시 특정 위치에서 고정 (fixed + relative 합성) */
    top: 0;
}

/* sticky: 평소엔 relative, 스크롤 시 fixed처럼 동작 */
```

### Q. CSS Custom Property (변수)를 어떻게 활용했나요?
**A.**
```css
:root {
    --red: #D42B2B;
    --red-h: #B82424;
    --bg: #F4F3F0;
    --text: #1A1A1A;
}

/* 사용 */
background: var(--red);
color: var(--text);
```
- 색상 테마를 한 곳에서 관리합니다.
- `:root`에 정의하면 전역에서 접근 가능합니다.
- `var(--red, #c00)` 처럼 폴백 값 지정도 가능합니다.

### Q. 반응형 웹 디자인이란? CSS Media Query를 설명하세요.
**A.**
```css
/* PC: 기본 스타일 */
.header-top { padding: 12px 24px; }

/* 모바일: 768px 이하 */
@media (max-width: 768px) {
    .header-top { padding: 8px 12px; }
    .header-actions { gap: 4px; }
    /* 불필요한 요소 숨김 */
    .header-date { display: none; }
}
```
- **Mobile First**: 작은 화면 기준으로 먼저 스타일 정의 후 `min-width`로 확장
- **Desktop First**: 큰 화면 기준으로 정의 후 `max-width`로 축소 (이 프로젝트 방식)

## 4. JavaScript 관련

### Q. fetch API로 좋아요를 어떻게 구현했나요?
**A.**
```javascript
async function toggleLike(newsId) {
    const btn = document.getElementById('btn-like');
    const isLiked = btn.dataset.liked === 'true';
    
    const res = await fetch(`/news/${newsId}/like`, {
        method: 'POST',
        headers: {'Content-Type': 'application/json'}
    });
    const data = await res.json();
    
    if (data.success) {
        btn.dataset.liked = data.liked ? 'true' : 'false';
        document.getElementById('like-count').textContent = data.count;
    }
}
```
- 페이지 새로고침 없이 서버와 통신 (AJAX)
- `async/await`으로 Promise를 동기처럼 처리
- 서버가 JSON으로 `{success: true, liked: bool, count: int}` 반환

### Q. 이벤트 위임(Event Delegation)이란 무엇인가요?
**A.**
- 여러 자식 요소에 개별 이벤트 리스너를 추가하는 대신, 부모에 하나만 추가하는 패턴
```javascript
// 나쁜 예: 댓글마다 이벤트 등록
document.querySelectorAll('.delete-btn').forEach(btn => {
    btn.addEventListener('click', deleteComment);
});

// 좋은 예: 부모에 위임
document.getElementById('comment-list').addEventListener('click', (e) => {
    if (e.target.classList.contains('delete-btn')) {
        deleteComment(e.target.dataset.commentId);
    }
});
```
- 장점: 메모리 절약, 동적으로 추가된 요소에도 자동 적용

### Q. WebSocket 클라이언트를 어떻게 구현했나요?
**A.**
```javascript
const ws = new WebSocket(`ws://${location.host}/api/chat/ws/${roomId}`);

ws.onopen = () => {
    console.log('채팅 연결됨');
};

ws.onmessage = (event) => {
    const data = JSON.parse(event.data);
    if (data.type === 'message') {
        appendMessage(data);
    } else if (data.type === 'read_receipt') {
        markMessagesRead();
    }
};

ws.onclose = () => {
    console.log('연결 해제');
    // 재연결 로직
};

// 메시지 전송
ws.send(JSON.stringify({
    sender: 'user',
    message: input.value,
    msg_type: 'text'
}));
```

### Q. `history.back()`은 어떻게 동작하나요?
**A.**
```javascript
// base.html의 뒤로가기 버튼
<button onclick="history.back()">← 뒤로가기</button>
```
- 브라우저의 세션 히스토리 스택에서 한 단계 뒤로 이동합니다.
- `window.history` 객체를 통해 브라우저 탐색 기록에 접근합니다.
- `history.back()` = `history.go(-1)`
- `history.forward()` = `history.go(1)`
- 히스토리가 없으면(첫 페이지) 아무 동작 없음

## 5. Jinja2 템플릿 관련

### Q. Jinja2 템플릿 상속이란?
**A.**
```html
<!-- base.html: 공통 레이아웃 -->
<html>
  <head>
    {% block head %}{% endblock %}  <!-- 자식이 채울 공간 -->
  </head>
  <body>
    {% block content %}{% endblock %}
  </body>
</html>

<!-- news_detail.html: 상속 -->
{% extends "base.html" %}        <!-- base.html을 상속 -->

{% block head %}                  <!-- head 블록 정의 -->
<link rel="stylesheet" href="/static/css/detail.css">
{% endblock %}

{% block content %}               <!-- content 블록 정의 -->
<h1>{{ news.title }}</h1>
{% endblock %}
```
- DRY(Don't Repeat Yourself) 원칙: 헤더/푸터를 매 파일에 복붙하지 않음
- 모든 페이지가 base.html을 상속하여 공통 `<html>` 구조 재사용

### Q. 서버에서 렌더링한 데이터를 JavaScript에서 어떻게 사용하나요?
**A.**
```html
<!-- 방법 1: data-* 속성 -->
<div data-news-id="{{ news.id }}" data-logged-in="{{ 'true' if current_user else 'false' }}">
```
```javascript
const newsId = document.querySelector('[data-news-id]').dataset.newsId;
```

```html
<!-- 방법 2: JS 변수에 직접 할당 -->
<script>
const NEWS_ID = {{ news.id }};
const IS_LOGGED_IN = {{ 'true' if current_user else 'false' }};
</script>
```

- Jinja2의 `{{ }}` 는 Python 값을 HTML에 출력
- 주의: XSS 방어를 위해 Jinja2는 기본적으로 HTML 이스케이프 처리

## 6. 성능 / UX 관련

### Q. CSS 버전 파라미터(`?v=3.8`)는 무엇인가요?
**A.**
```html
<link rel="stylesheet" href="/static/css/main.css?v=3.8">
```
- 브라우저는 URL이 같으면 캐시된 파일을 사용합니다.
- CSS를 수정했을 때 `?v=3.8` → `?v=3.9`로 바꾸면 브라우저가 새로 다운로드합니다.
- 이를 **캐시 버스팅(Cache Busting)**이라 합니다.

### Q. `position: sticky`와 `position: fixed`의 차이는?
**A.**
- `fixed`: 항상 뷰포트에 고정 (스크롤 위치 무관)
- `sticky`: 일반 흐름 유지하다가 지정 위치(top: 0)에 도달하면 fixed처럼 동작
- 이 프로젝트: `site-header { position: sticky; top: 0; }` → 헤더가 스크롤을 따라가다 화면 상단에 붙음

### Q. `overflow: hidden`은 언제 사용하나요?
**A.**
- 자식 요소가 부모를 넘쳐 나오는 것을 숨깁니다.
- 이 프로젝트: 뉴스 티커(흐르는 텍스트) 영역 클리핑에 사용
```css
.news-ticker-pill {
    overflow: hidden;       /* 티커 텍스트가 영역 밖으로 나오면 숨김 */
    width: 230px;
    white-space: nowrap;    /* 줄바꿈 없이 한 줄 유지 */
}
```

## 7. 보안 관련

### Q. XSS(Cross-Site Scripting) 공격을 프론트에서 어떻게 방어하나요?
**A.**
- Jinja2 템플릿은 기본적으로 `{{ variable }}`을 HTML 이스케이프합니다.
  - `<script>alert(1)</script>` → `&lt;script&gt;alert(1)&lt;/script&gt;`
- `| safe` 필터를 사용하면 이스케이프를 비활성화 → 신뢰하는 내용에만 사용
- `httponly` 쿠키 설정으로 JS에서 인증 쿠키 접근 불가

### Q. CSRF 공격이란? 이 프로젝트에서 어떻게 방어했나요?
**A.**
- CSRF(Cross-Site Request Forgery): 로그인된 사용자의 권한으로 악의적인 사이트가 요청을 보내는 공격
- 이 프로젝트: `SameSite=Lax` 쿠키 설정으로 외부 사이트에서 발생한 요청에는 쿠키 미전송
- 완전한 방어를 위해서는 CSRF 토큰도 사용해야 합니다.
