## 1. HTTP 메서드와 상태 코드

| 메서드 | 용도 | 이 프로젝트 예시 |
|--------|------|-----------------|
| GET | 데이터 조회 | `/news`, `/search`, `/mypage` |
| POST | 데이터 생성 | `/signup`, `/login`, `/subscribe` |
| PUT | 데이터 전체 수정 | `/news/{id}/comments/{cid}` |
| DELETE | 데이터 삭제 | `/news/{id}/comments/{cid}` |

| 상태 코드 | 의미 | 사용 예 |
|-----------|------|---------|
| 200 | OK | 정상 응답 |
| 303 | See Other | 폼 제출 후 리다이렉트 (Post/Redirect/Get 패턴) |
| 400 | Bad Request | 잘못된 요청 |
| 401 | Unauthorized | 로그인 필요 |
| 403 | Forbidden | 권한 없음 (admin만 접근 가능) |
| 404 | Not Found | 리소스 없음 |
| 429 | Too Many Requests | Rate Limit 초과 (Groq API) |
| 500 | Internal Server Error | 서버 오류 |

**PRG 패턴 (Post-Redirect-Get):**
- 폼 제출(POST) → 처리 → 리다이렉트(303) → 결과 페이지(GET)
- 새로고침 시 폼이 중복 제출되는 것을 방지합니다.
- 이 프로젝트에서 `/signup`, `/subscribe` 등 모두 이 패턴 사용

## 2. 쿠키의 보안 속성

```
Set-Cookie: newsletter_user=user123; HttpOnly; SameSite=Lax; Path=/
```

| 속성 | 의미 | 미설정 시 위험 |
|------|------|---------------|
| `HttpOnly` | JS로 접근 불가 | XSS로 쿠키 탈취 가능 |
| `SameSite=Lax` | 같은 사이트 요청에만 전송 | CSRF 공격 가능 |
| `Secure` | HTTPS에서만 전송 | HTTP 통신 시 탈취 가능 |
| `Max-Age` | 만료 시간 설정 | 없으면 브라우저 종료 시 삭제 |

**이 프로젝트의 쿠키 설정:**
- `httponly=True`, `samesite="lax"` ✅
- `Secure` 미설정 (로컬 환경은 HTTP) → 프로덕션에서는 `secure=True` 필요

## 3. CORS (Cross-Origin Resource Sharing)

- **Same-Origin Policy**: 브라우저는 기본적으로 다른 출처의 API 요청을 차단합니다.
- **Origin = Protocol + Domain + Port**: `https://example.com:443`

```python
# 현재 설정 (개발 편의용)
app.add_middleware(CORSMiddleware, allow_origins=["*"])

# 프로덕션 권장 설정
app.add_middleware(
    CORSMiddleware,
    allow_origins=["https://newsdeliver.onrender.com"],
    allow_methods=["GET", "POST"],
    allow_credentials=True,   # 쿠키 포함 요청 허용 (이때 *는 불가)
)
```

**이 프로젝트가 `["*"]`를 써도 큰 문제 없는 이유:**
- SSR 구조라 API를 다른 도메인에서 직접 호출하는 시나리오가 거의 없음
- 쿠키 인증이므로 `allow_credentials=True` 없이는 실제 인증이 안 됨

## 4. SQL 기초 — 이 프로젝트에서 자주 쓰인 패턴

### JOIN
```sql
-- 뉴스 + 카테고리명 함께 조회
SELECT n.*, c.name AS category_name
FROM news n
LEFT JOIN categories c ON n.category_id = c.id
WHERE n.status = 'published'

-- 댓글 + 좋아요 수 + 작성자명 동시 집계
SELECT c.id, c.content, u.name, COUNT(cl.id) AS like_count
FROM news_comments c
JOIN news_users u ON c.user_id = u.id
LEFT JOIN comment_likes cl ON cl.comment_id = c.id
GROUP BY c.id, c.content, u.name
```

### 페이지네이션
```sql
SELECT * FROM news
ORDER BY created_at DESC
LIMIT 20 OFFSET 40   -- 3페이지 (0-based: 2×20=40)
```

### Upsert
```sql
-- 있으면 무시, 없으면 삽입
INSERT INTO news (title, ...) VALUES (...) ON CONFLICT DO NOTHING

-- 있으면 업데이트, 없으면 삽입
INSERT INTO subscriptions (user_id, email) VALUES (...)
ON CONFLICT (user_id) DO UPDATE SET email = EXCLUDED.email
```

### PostgreSQL 전용 문법
```sql
ILIKE '%keyword%'             -- 대소문자 무시 LIKE
COALESCE(view_count, 0)       -- NULL이면 0 반환
CURRENT_DATE                  -- 오늘 날짜
DATE(created_at) = CURRENT_DATE  -- 날짜 비교
array_position(ARRAY[...]::text[], name)  -- 배열에서 위치 (정렬용)
```

## 5. 트랜잭션과 ACID

- **Atomicity (원자성)**: 작업이 모두 성공하거나 모두 실패해야 함
- **Consistency (일관성)**: 트랜잭션 전후 DB가 일관된 상태 유지
- **Isolation (격리성)**: 동시 트랜잭션이 서로 간섭하지 않음
- **Durability (지속성)**: 커밋된 데이터는 영구 보존

이 프로젝트에서의 적용:
```python
engine = create_engine(settings.DB_URL, isolation_level="READ COMMITTED")
# READ COMMITTED: 커밋된 데이터만 읽음 (Dirty Read 방지)

with engine.connect() as conn:
    conn.execute(text("DELETE FROM news_comments WHERE user_id = :id"), ...)
    conn.execute(text("DELETE FROM news_likes WHERE user_id = :id"), ...)
    # ... 여러 테이블 삭제
    conn.commit()   # 모두 성공 시 한 번에 커밋
    # commit 전 오류 발생 시 자동 롤백
```

## 8. WebSocket 프로토콜

```
HTTP 요청         → 101 Switching Protocols  (WebSocket 업그레이드)
WebSocket 연결 유지 ↔ 양방향 메시지 스트림
WebSocket 종료    → WebSocketDisconnect
```

```javascript
// 클라이언트 (브라우저)
const ws = new WebSocket(`ws://localhost:8000/api/chat/ws/${roomId}`);
ws.onopen = () => ws.send(JSON.stringify({sender: "user", message: "안녕"}));
ws.onmessage = (e) => console.log(JSON.parse(e.data));
ws.onclose = () => console.log("연결 해제");
```

**이 프로젝트의 WebSocket 흐름:**
1. 유저/관리자가 `/api/chat/ws/{room_id}` 연결
2. 메시지 전송 → DB 저장 → 같은 room의 모든 소켓에 broadcast
3. `WebSocketDisconnect` 예외 발생 시 connections 목록에서 제거

## 9. Rate Limiting 대처 전략

**이 프로젝트의 Groq API Rate Limit 처리:**
```
분당 10회 = 6초에 1회
→ _MIN_INTERVAL = 6.0
→ threading.Lock()으로 직렬화
→ 429 발생 시 최대 5번 재시도
→ 뉴스레터 발송 중에는 fast_fail=True (블로킹 방지)
```

**일반적인 Rate Limit 대처 방법:**
1. **쿨다운**: 최소 간격 보장 (sleep)
2. **지수 백오프**: 재시도마다 대기 시간을 2배씩 증가 (`min(2 ** attempt, 30)`)
3. **Circuit Breaker**: 연속 실패 시 일정 시간 동안 요청 중단
4. **큐 기반 처리**: 요청을 큐에 쌓고 한 번에 하나씩 처리

## 12. 데이터베이스 설계 — 14개 테이블

| 테이블 | 역할 |
|--------|------|
| `news_users` | 회원 정보 (id, pw, oauth_provider, role) |
| `categories` | 카테고리 목록 |
| `news` | 뉴스 기사 (is_global: 0=국내, 1=해외) |
| `subscriptions` | 이메일 구독 (is_verified, verify_token) |
| `category_subscriptions` | 유저-카테고리 구독 연결 테이블 |
| `email_logs` | 이메일 발송 기록 |
| `newsletter_sent` | 중복 발송 방지 기록 |
| `news_likes` | 기사 좋아요 (user_id, news_id, UNIQUE) |
| `news_comments` | 댓글 (parent_id로 대댓글 구조) |
| `comment_likes` | 댓글 좋아요 |
| `bookmarks` | 북마크 (user_id, news_id, UNIQUE) |
| `reports` | 기사 신고 |
| `chat_rooms` | 채팅방 (user당 카테고리별 1개) |
| `chat_messages` | 채팅 메시지 (sender, message_type, is_read) |

**핵심 설계 패턴:**
- `UNIQUE(user_id, news_id)`: 한 유저가 같은 기사를 좋아요/북마크 두 번 불가
- `UNIQUE(email, news_id)`: 동일 이메일에 동일 기사를 중복 발송 불가
- `parent_id`: 댓글-대댓글 자기 참조 (Self-referential) 관계
- `is_global SMALLINT`: 0/1로 국내/해외 구분 (Boolean 대신 SMALLINT로 PostgreSQL 호환성 확보)

## 13. 비밀번호 보안 문제 (이 프로젝트의 한계)

**현재 상태:** 비밀번호를 평문(plain text)으로 DB에 저장 중
```sql
SELECT * FROM news_users WHERE id = :id AND pw = :pw   -- 평문 비교
```

**실무에서는 반드시:** 해시(bcrypt, argon2) 저장
```python
# bcrypt 예시
import bcrypt
hashed = bcrypt.hashpw(password.encode(), bcrypt.gensalt())  # 저장
bcrypt.checkpw(password.encode(), hashed)                     # 검증
```

**면접 포인트:** "현재 평문 저장 중이며, 이는 보안 취약점입니다. bcrypt를 적용하면 DB가 유출되더라도 비밀번호를 바로 알 수 없습니다."

## 14. Jaccard 유사도 (뉴스 중복 제거)

이 프로젝트에서는 DB unique 인덱스(title)로 중복을 방지하지만, 제목이 조금 다른 유사 기사 중복을 막으려면 Jaccard 유사도를 사용합니다.

```python
def jaccard_similarity(a: str, b: str) -> float:
    set_a = set(a.split())
    set_b = set(b.split())
    intersection = len(set_a & set_b)
    union = len(set_a | set_b)
    return intersection / union if union else 0.0

# 0.35 이상이면 중복으로 판단
if jaccard_similarity(new_title, existing_title) >= 0.35:
    skip()
```
